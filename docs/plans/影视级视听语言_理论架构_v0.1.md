## 零、问题定义：这里的「电影级」指什么

使用者已明确划界：电影级 = **运镜、构图、场景搭配、语言、动作、氛围**的艺术设计，
**不是**像素多精美、多写实。

这个定义是全部架构的地基。它把问题从「渲染器能力」移到了**决策的可表达性与可判定性**：

| 如果电影级 = 像素质量 | 如果电影级 = 视听语言决策（本项目口径） |
|---|---|
| 解法是换渲染器 / 提采样 / 上光追 | 解法是**把决策写成数据、把好坏写成判据** |
| 瓶颈在算力 | 瓶颈在**手艺的显式化** |
| 评价靠肉眼比对 | 评价靠**可复跑读数** |

⇒ 本架构不追求更写实的渲染，只追求**让每一门视听手艺可声明、可判定、可复现、可迭代**。

## 一、理论地基：六条命题

### 命题 1 · 可判定性（架构的准入门槛）

一门手艺要能被 AI **稳定**复现，必须同时具备三件东西：

1. **显式声明**——这门手艺的参数以数据形式写下来（不是藏在代码的 if 链里）；
2. **可计算判据**——给定产物，能算出「合不合规 / 够不够」；
3. **可复跑读数**——同一输入重跑得同一读数。

三件缺一即失效：缺①→不可控（每次靠现场发挥）；缺②→不可验收（只能靠「我觉得」）；缺③→不可回归（改一处崩一处）。

> **硬规则**：凡三件不齐的手艺，系统**不得声称具备该能力**。只能登记为 DEFER（交使用者裁）或 BLINDSPOT（待补理论）。
> 这条是防止「用形容词冒充能力」的唯一闸门。

### 命题 2 · 意图与执行分离（LLM 的位置）

LLM 的不可复现性与确定性产线必须被**结构性隔离**，而不是靠「提示词写好一点」调和。

```
   自然语言创意 ──[LLM 编译期]──→ 契约文档 ──[零 LLM 执行期]──→ 产物
        │                              │                        │
        │                        校验器 + 判据库            渲染器回读真值
        └────────── 此处允许不确定 ────┴──── 此处必须逐字节确定 ────┘
```

- LLM **只在编译期**出现：把意图翻译成契约文档，不做执行；
- 契约 → 产物的路径**零 LLM**：纯函数 + 落地器；
- 判据在**两个阶段都跑**：编译期拦明显不合规的候选，执行期验证真实产物。

这正是仓内既有的 **「引导 → 固化 → 零 LLM」** 链条在影视层的投影（见 `docs/theory/世界模型理论_白箱固化_v1.md`）。

### 命题 3 · 时间化单一真源

既有 `wmfactory.spec/1` 已经实现「同一件东西在几何 / 材质 / 渲染 / 矢量 / 动画四处不漂移」——
这是六轮返工换来的（见 `factory/geo/spec.py` 头部）。

影视级的**全部新增量都是时间函数**：相机在动、灯在变、表演在演进、剪辑在推进。
若各自为政，必然重演那族病——`factory/geo/assembly.py` 头部逐字记载过：机械臂 `shapes.json` 拿的是动画末帧 u=1 的姿态，而 `oracle.jsonl` 的 tick 0 是另一个姿态。

> **架构约束**：
> 1. 一切时间演化必须经**统一时间核**（`lingshu/world/time_core.py` 已钉死「核形状唯一」），影视层**不得**新起缓动 / 衰减实现；
> 2. 镜头层与表演层**共享同一帧基**（fps / frame_start / frame_end 一律取自 `spec.scene`，不得自定）。

### 命题 4 · 真值外部性

判据的可信度上限 = 真值的独立性。

`wm_bridge/DESIGN.md` 已明确记载一条教训：世界模型 L5 的 `verify()` 设计为「外部观察者逐 tick 对比」，
但 `actual` 取自**仓内自己写的模拟器**——典型的**自己评自己**。

影视层必须复制这条教训：

> **「画面参数」的真值必须从渲染器回读**（实际覆盖率 / 实际机位 / 实际曝光 / 实际剪影面积），
> **不得采信声明的意图**。这就是下文的「腿 C · 视听真值」。

### 命题 5 · 四态贯穿

每一个视听选择都必须落四态之一：

| 态 | 判据 | 处置 |
|---|---|---|
| **ACCEPT** | 有权威来源 + 参数在域内 + 判据通过 | 执行并归档 |
| **REJECT** | 违反硬约束（越轴 / 视线不匹配 / 拍点漂移超窗 / 主体出画） | fail-closed 拒收 |
| **DEFER** | **取向问题**（风格、色彩情绪映射、母题选择） | 交使用者裁，不硬做 |
| **BLINDSPOT** | **理论未覆盖** | **不得临时发明**（第 12 条：算法权威唯一），记档并驱动补理论 |

这一条把「**艺术判断归使用者、事实判据归系统**」落成了可执行规则。

### 命题 6 · 负记忆驱动收敛

审美改进不靠「更努力」，靠**把每次「哪里难看」固化成负记忆 + 新判据**。

`factory/_lead/hero_render.py` 的 `ITERATIONS` 段已是雏形——文件头写明「把每一轮『哪里难看』记在文末」。
本方案把它从**习惯**正式化为**强制环节**：

```
现象（哪里难看） → 根因（为什么难看） → 新判据 / 新不适用条件 → 归档 → 下次自动拦住
```

## 二、既有地基盘点：我们已经有什么

架构不新建，只在既有骨架上**升维**。既有资产（路径为仓内相对路径）：

### 2.1 四条产线（由同一份 spec 驱动）

| 产线 | 契约 | 关键件 | 已实现 |

| **绘画** | `wmshade.material/1` · `wmshade.render/1` | `factory/shade/material.py` · `render.py` · `bpy_shade.py` | 材质配方（角色→节点图）· 相机/灯光/渲染配方 · 色彩管理两档 |
| **矢量** | — | `factory/vec/svg.py` · `smil.py` · `bpy_vec.py` | 分层彩色 SVG · SMIL 时间轴 · HLR 隐藏线消除 |
| **动画** | `wmfactory.rig/1` | `factory/anim/rig.py` · `eval.py` · `seq.py` | 骨骼/驱动器声明 · 纯函数运动求值 `eval_at(spec, frame)` · 自写 PNG 编码器（逐字节确定）· 真 GIF |

### 2.2 既有工程纪律（新层必须继承）

- **闭集 + fail-closed**：`JOINT_KINDS` / `JOINT_EASINGS` / `MATERIAL_ROLES` / `SHOT_KINDS` / `LIGHT_TYPES` 全是闭集；
  `_reject_unknown` 对未声明键直接 raise——因为拼错的键名会被 `dict.get` **静默忽略**，导致几何/旋转无声改变。
- **量化与可哈希**：`QUANT = 6`，`canonical_json` + `recipe_digest`（sha256）——配方可 diff、可版本控制。
- **确定性分档**：EEVEE 的 PNG **逐字节不可复现**但**像素可完全一致**；仓内给了 `determinism.fast` / `determinism.strict` 两套口径，
  判据用「canonical PNG 的 sha256」或「解像素零差」，**不假装 Blender 原始 PNG 的 md5 是好判据**。
- **既有门禁范式**：`factory/*/_det/gate_*.py`（`gate_gait_contact` / `gate_physics` / `gate_crease_adaptive` / `gate_svg_iou`）。
  **判据库不是新发明，是这个既有范式的系统化。**
- **三条硬边界**（`wm_bridge/DESIGN.md`）：
  B1 不改 `world/`；B2 不把 bpy 带进 `lingshu`；B3 原版插件零改动。
  以及 D-005：`world/` 纯标准库、零外部依赖。

## 三、架构：七层 + 契约族

### 3.1 分层（依赖方向：上层只读下层，不反向）

```
L6  交付层  MV 母版 ── 视频 + 音轨 + 字幕 + 元数据清单
       ↑
L5  剪辑层  edit  ── 镜头表 · 转场 · 卡点 · 节奏
       ↑
L4  镜头层  shot  ── camera · compose · light · perform   ← 【本方案的主战场】
       ↑
L3  表演层  perform ── 动作语义 → joints
       ↑
L2  场景层  scene ── spec/1（物与姿态）＋ set dressing（场景搭配）
       ↑
L1  几何层  geo  ── parts · assembly · mesh_gen · skeleton3d     【已有】
       ↑
L0  真值层  oracle ── 真值导出 · manifest · 回读对拍              【已有，需扩视听面】
```

**落点（已裁 D3，2026-10-16）**：新增层（L2 场景搭配、L3–L6）全部落在
`bridges/blender/wm_bridge/factory/` 之下（与既有四产线同层），**不新建 `wmfilm/` 平行包**。
沿用既有「一契约一模块 + `_det/` 门禁子目录」习惯（`factory/geo/spec.py`、`factory/anim/_det/` 等）：

```
factory/film/            # 影视层新代码（L2–L6 新增契约与实现）
    shot.py             # wmfilm.shot/1   —— 镜头（camera · compose · light）
    perform.py          # wmfilm.perform/1 —— 表演语义覆写
    score.py            # wmmv.score/1    —— 乐谱（离线分析后固化）
    bind.py             # wmmv.bind/1     —— 音画绑定
    edit.py             # wmmv.edit/1     —— 剪辑时间轴 / 转场
    text.py             # wmmv.text/1     —— 歌词 / 字幕 / 字卡
    oracle.py           # wmfilm.oracle/1 —— 视听真值回读
    _det/               # 判据门 gate_*.py（沿用既有 _det/ 命名约定）
```

L1 几何层继续由 `factory/geo/`（已有）供货；L0 真值层由 `wm_bridge` 既有 oracle 供货并**扩视听面**（§3.3 腿 C）。
`spec/1` 仍在 `factory/geo/spec.py`（唯一输入契约，**不动**）。

分层理由与 `world/` 的「core 不导入 world」同构：**下层不知道上层存在**，
因此几何层永远可以在没有 Blender、没有音乐的机器上自测（这正是既有四产线能在 CI 上跑的原因）。

### 3.3 两条腿 → 三条腿

`wm_bridge/DESIGN.md` 已立两条腿：**腿 A 外部观察者/真值源**、**腿 B 几何供货**。
影视层加**腿 C**：

| 腿 | 方向 | 内容 |
|---|---|---|
| A | Blender → 世界模型 | `oracle.jsonl` 逐 tick 真值（已有） |
| B | Blender → 世界模型 | 几何 / 锚点供货（已有） |
| **C** | **渲染器 → 判据库** | **实际覆盖率 · 实际机位 · 实际曝光 · 实际剪影 · 实际拍点对齐** |

腿 C 是命题 4 的落地：**判据必须吃回读的真值，不吃声明的意图。**

**设计要点（每条都有理由）**：

1. `spec_ref.digest` 绑定物与姿态——防止「镜头用的模型和渲染用的模型不是同一版」；
2. `frame_base` 必须与 `spec.scene` 一致——防止帧基漂移（命题 3）；
3. `camera.path` 是**时间函数**不是单点——这是 G1 缺口的正面回答；
4. 所有枚举**闭集 + fail-closed**——沿用 `_reject_unknown` 的既有纪律；
5. `coverage_target` 复用既有 hero 的 0.68——**不新造口径**；
6. `compose.aspect_ratio = 1.778`（16:9 横屏，已裁 D4）——全片统一基准 1920×1080（可选 3840×2160，同 16:9）；
7. **16:9 字幕安全区**，沿用附录已录口径：
   `title_safe = 0.80 × 画幅`（EBU R95；1920×1080 下为 1536×864 px）、
   `action_safe = 0.90 × 画幅`（EBU R95；1920×1080 下为 1728×972 px）；
   文本层 `wmfilm.text/1` 采纳 Netflix 口径（附录第一部分④）：CPS ≤ 20、每行 ≤ 42 字符、同屏 ≤ 2 行；
8. **竖屏 9:16 不在本版范围**——若日后做竖屏 MV，须单独补 9:16 的安全区、行宽与构图参数，不得复用本版 16:9 数值。

## 三·五、依赖分层范式（新层必须遵守）

**「身体库可以重依赖」在灵枢的语境里不等于「可以随便依赖」。** 既有设计的核心是：
把重依赖**关进声明面**，让轻核永不被污染。

### 3.5.1 既有设计（逐条取证）

**① 轻核零依赖是硬承诺**——`pyproject.toml:18` 的 `dependencies = []`：装 `lingshu` 本体**不拉任何第三方**。
`docs/architecture.md` §三 原文：「**轻核承诺**：`core` 不因本仓的『完整』而增重——可单独安装、单独运行」。

**② 重依赖按 extra 分层声明**（`pyproject.toml:31-34`）

| extra | 内容 |
|---|---|
| `world` / `nn` / `gen` | `numpy>=2.3.5,<2.6` ＋ `Pillow>=12.3,<13` |
| `full` | 同上（四层并集） |

**③ 大体积依赖走 sub-extra，命名约定 `<层>-<用途>`**（`pyproject.toml:35-51`）

| sub-extra | 依赖 | 用途 |
|---|---|---|
| `core-sparse` | `scipy` | `core/activation.py:56` 可选稀疏后端 |
| `nn-train` | `pyarrow` | `nn/hex_train.py:40` parquet 语料加载 |
| `gen-diffusion` | `torch` · `diffusers` | `gen/hexgen_multi_seed.py:88-89` 黑箱多 seed 渲染 |

**关键：这些一律不进 `full`**——理由逐字写在 `pyproject.toml:36-38`：
「CI 装 `.[full,dev]`，**不该被 GB 级 torch 拖垮**」。

**④ 两级 import 范式**

| 档 | 写法 | 实例 |
|---|---|---|
| **常规路径** | 模块级 import（已声明在 extra 里） | `numpy` 在 world / nn / gen 各模块顶部 |
| **可选重载** | **只在函数体内** import，缺则调用点 `ImportError` | `world/anim.py:98` 的 PIL——源码带 `# noqa: PLC0415 —— 刻意函数内 import`；`gen/hexgen_multi_seed.py:88` 的 torch |

**⑤ 缺失时的行为：显式声明，不静默降级**（`docs/intake/body-export-v0.1/README.md` §三）

| 情形 | 行为 |
|---|---|
| 扩展接口缺失 | 返回 `BLINDSPOT` / `gen_not_ready`（源码原文：「没有则**诚实声明** BLINDSPOT（公开仓库形态）」） |
| 未实现扩展点 | 函数内 `try/except` 降级为空实现 |
| `scipy` 缺失 | 降级 **edge-list 传播**（局限已在源码内声明） |
| Rust 后端缺失 | 走纯 Python 路径 |

**⑥ 版本区间口径：只在实测矩阵内承诺**（`pyproject.toml:46-48`）——
`scipy` / `pyarrow` / `torch` / `diffusers` **如实不设区间**，原文：「要设区间须先补实测矩阵」。

**⑦ 守卫强制声明面**（`tests/test_issue253_extras_declared_guard.py`）

- A / B 组：各层**每一个**第三方导入都必须在「层 extra ∪ 层 `层-*` sub-extra」里找到声明面；
- B′ 组：`world` extra **本层**必须带 Pillow（**不接受**靠 sub-extra 顶）；
- C-2 组：**变异自证**——删掉 sub-extra，检查器**必须报红**；无判别力即失败。

### 3.5.2 对本层的含义（已裁决）

使用者裁定：**身体库可以重依赖**。⇒ 原 D2「librosa vs 预计算 JSON」**落定**：

1. **可以引入 `librosa`**——不再受「D-005 零依赖」束缚；
2. 但必须按既有范式落成 sub-extra，建议名 **`film-audio = ["librosa"]`**（遵 `<层>-<用途>` 命名约定）；
3. **只在函数体内 import**（分析函数内），**不进 `full`**；
4. **版本区间如实不设**（librosa 未入实测矩阵，遵 ⑥ 口径）；
5. 必须过 `test_issue253_extras_declared_guard.py` 式守卫，**含变异自证**。

**同时澄清一条易混边界——D-005 的适用范围**：

| 约束 | 对象 | 新层是否受约束 |
|---|---|---|
| **D-005 零依赖** | `lingshu/world/` 的**核心路径**（`world_model.py` 头部「纯标准库 · 零外部依赖」） | ❌ **不约束新层** |

## 四、判据库：把「好看」变成断言

### 4.1 三级门（本方案最重要的设计规则）

调研结果把每条参数标了性质：`[标准]` / `[共识]` / `[经验]` / `[风格]`。
**这个标注决定了它能进哪一级门**：

| 门 | 准入 | 行为 | 例 |
|---|---|---|---|
| **G1 硬门** | 只收 `[标准]` + `[共识]` | **REJECT**，fail-closed 拒收 | 越轴（180° 规则）· 字幕 CPS > 20 · 拍点漂移 > 1 帧 · 主体出画 |
| **G2 软门** | 收 `[经验]` | **告警 + 读数**，不拦 | headroom 不在 3%~12% · key:fill 不在 2:1~8:1 |
| **G3 记录** | 收 `[风格]` | **只登记，供人裁（DEFER）** | 黄金分割 vs 三分法 · 色彩情绪映射 · 母题重复策略 |

> **为什么必须有这个分级**：否则系统会**用任意口味去硬拦创作**。
> 调研已证实若干流传甚广的「规则」其实**实证支持不足**——
> 例如黄金分割相对三分法的美学优势「在实证研究中**未获稳定支持**」，
> 色彩情绪映射「跨文化一致性弱，实证支持不足」，Kuleshov 效应的现代复现「存在分歧」。
> **这些一律不得进 G1。** 这正是命题 5 中 DEFER 与 ACCEPT 的分界线。

### 4.3 判据的变异自证（继承既有纪律）

每条判据必须配一条变异：

```
C2 三分法偏差：把 subject_anchor 从 left_third 改成 center → 偏差读数须上升并越阈值
K1 轴线一致  ：把 shot_04 的相机镜像到轴线另一侧 → 必须 REJECT
E1 卡点对齐  ：把切点挪 3 帧 → 偏差读数须 > 1 帧并 REJECT
```

**只有变异能把它判红的判据，才算真判据。** 这直接继承第 5 条（验证纪律）与既有守卫文化。

## 五、LLM 的位置：只做意图编译

### 5.1 职责边界

| 阶段 | 谁做 | 允许不确定？ |
|---|---|---|
| 创意意图 → 契约候选 | **LLM** | ✅ 允许 |
| 契约候选 → 校验 + 判据 | 校验器（零 LLM） | ❌ |
| 契约 → 产物 | 纯函数 + 落地器（零 LLM） | ❌ |
| 产物 → 真值回读 | 渲染器（零 LLM） | ❌ |
| 真值 → 判据裁决 | 判据库（零 LLM） | ❌ |
| DEFER 项裁决 | **使用者** | ✅ |

### 5.2 编译期的输入输出契约

- **输入**：自然语言创意（「这首歌讲离别，副歌要爆发」）+ 音乐分析读数 + 既有资产清单
- **输出**：`wmfilm.shot/1` · `wmmv.bind/1` · `wmmv.edit/1` 的**候选文档**（JSON，不是代码）
- **约束**：LLM **只能**在闭集内取值；越界即被 `_reject_unknown` 拒收
- **固化**：候选通过 → 落盘 → `digest` 记账 → 此后**零 LLM 可完整复现**

> 这条保证：**LLM 的不可复现性被压缩在编译期一次**，产物侧永远逐字节可复现。

### 5.3 为什么不许 LLM 直接出画面

因为那样就违反了命题 1——**没有显式声明，就没有判据，就没有读数**。
一个「看起来不错」的产物如果不可复跑、不可回归，它在工程上等于不存在。

## 六、真值面：视听真值 `wmfilm.oracle/1`

### 6.1 回读字段（从渲染器实际测量，非声明）

```jsonc
{
  "schema": "wmfilm.oracle/1",
  "shot_id": "shot_03",
  "frame": 72,
  "measured": {
    "coverage_actual": 0.671,          // 实测主体覆盖率（非 coverage_target）
    "camera_actual": {"pos": [...], "quat": [...], "focal_35eq": 59.8},
    "subject_bbox_screen": [x0,y0,x1,y1],
    "silhouette_delta_L": 0.21,
    "histogram": {"p05": 0.03, "p50": 0.31, "p95": 0.88},
    "color_temp_est_k": 4180
  },
  "manifest": {"algorithm": "sha256", "files": {...}}

```

### 6.2 为什么必须有

因为 `wm_bridge/DESIGN.md` 已经吃过这个亏：**自己评自己**。
「声明的 coverage = 0.68」和「实际渲出来的覆盖率 = 0.671」是两件事——
前者是**意图**，后者是**事实**。判据必须吃事实。

这与既有 `wm_bridge.contract`（schema 校验 + NaN/Inf 门）同构：

## 七、实施路线 P0–P7（骨架优先，已裁 D1/D4/D5）

**全流程常数（已裁 D4）**：画幅 **16:9 横屏**，基准分辨率 1920×1080（可选 3840×2160，同 16:9）。

#### 7.2.1 判据的输入与缺料行为（**本批最重要的设计**）

§六.2 定死「判据必须吃事实」，但 §3.2 的七份契约**只承载声明，不承载实测**。本批没有回避这个缺口，
而是对每条判据写明**输入来自声明还是事实**、以及**缺料时怎么办**：

| 判据 | 输入 | 缺料行为 |
|---|---|---|
| K1 轴线一致 | 声明（机位）+ 场景轴线 | 无轴线 ⇒ BLINDSPOT |
| K2 视线匹配 | **事实** `subject_gaze_screen`（§六.1 未列 —— **契约缺口**） | 无 ⇒ BLINDSPOT |
| K3 屏幕方向 | **事实** `subject_motion_screen` 或相邻帧 bbox 位移 | 无 ⇒ BLINDSPOT |
| K4 30° 规则 | 声明（相邻镜头首帧机位） | 缺镜头契约 / 瞄准点不唯一 ⇒ BLINDSPOT |
| K5 景别跳跃 | **事实** `subject_bbox_screen` | 无 ⇒ BLINDSPOT |
| E1 卡点对齐 | 声明（切点）+ 乐谱（强拍） | 无 edit / 无 score / 无 downbeats ⇒ BLINDSPOT |

**核心不变式：缺料绝不得变成 ACCEPT。** 缺什么由此变成**可归档的读数**，驱动下一轮补契约 ——
而不是一个永远为绿的伪判据。守卫 `test_e8_blindspot_never_silently_passes` 钉死这条。

#### 7.2.2 K4 与 K5 的关系（**为什么不是重复**）

K4 吃**声明**、K5 吃**事实**，二者对「同机位 + 同景别」这个跳切判同一结论，但**数据来源与读数不同** ——
这使二者在只有声明、或只有事实时各有一条能跑。差别在于 K4 会误杀 **cut-in**（机位几乎不动、
景别猛跨级，如 wide → extreme_close），故 K4 的不适用条件（`K4_NEGATIVE`）明写 cut-in 应改由 K5 判；
K5 的条件是「微变**且**机位夹角 < 30°」才 REJECT，于是 cut-in 由 K5 放行。
守卫 `test_b3_k5_allows_same_scale_when_angle_ge_30` 钉死「换机位时同景别是合法剪辑，K5 不得误杀」。

#### 7.2.3 变异自证（§4.3）实测

每条判据都做了**两相断言**（正常料 ⇒ 该判的态；定向变异 ⇒ 必须 REJECT）：

| 变异 | 读数 | 结果 |
|---|---|---|
| K4：s2 机位挪到夹角 11.3°（< 30°） | 44.8° → 11.3° | REJECT ✅ |
| K5：同机位 + 同景别（高度相同） | 相对差 0.000，夹角 11.3° | REJECT ✅ |
| K1：s2 机位镜像到轴线另一侧 | 侧向符号 +1 → −1 | REJECT ✅ |
| E1：切点从第 48 帧挪到第 51 帧 | 偏差 0 → +3 帧（> 容差 1） | REJECT ✅ |
| K2：两镜视线同向（都看画右） | 符号 (+1, +1) | REJECT ✅ |
| K3：相邻镜头主体运动方向异号 | 符号 (+1, −1) | REJECT ✅ |

还原即绿 —— 只有变异能把它判红的判据，才算真判据。

#### 7.2.4 本批发现并修掉的五处缺陷（**全部由测试抓到，非事后猜测**）

1. **判据族闭集错列**：把「契约族」与「判据族」混为一谈，写成 `K/E/M/P/T/A` ——
   漏了 **C（构图）**、凭空多了 **T（文本）**，于是 `C1` 直接过不了 `family_of`。
   根因：§4.2 登记的是**六族 C/M/K/E/A/P**；文本类校验（CPS / 行宽 / 安全区）在 §4.2 里
   **没有编号**，是在 `wmmv.text/1` **契约层**硬拦的。修法：闭集改为 `C/M/K/E/A/P`，
   并新增 `SCHEMA_ENFORCED` 登记表诚实记录「契约层已拦、故不进判据登记」的校验
   （T1/T2/T3 + M2 缓动 + E4 转场闭集），避免报告上看起来像「没做」。
2. **DEFER 的 measured 规则错位**：契约把意图（**不得编造读数**）错写成形式
   （**不得出现 `measured` 键**）。后果：所有判据门天然统一产出 `measured: []`（「无读数」的
   自然表示）却被判违规，逼每个生产者特判 —— 而特判点正是漏判高发处。
   修法：规则改为「DEFER 不得带**非空** measured」；**规则定在内容上，而非键是否存在上**。
3. **BLINDSPOT 的 measured 义务过强**：原规则要求 BLINDSPOT 必须带非空 `measured` ——
   而其语义正是「跑了但判不了」，缺料时往往一条读数都没有；强制非空会把「缺料」逼成「编一个读数」。
   修法：`_NEEDS_MEASURED` 收窄为 `("ACCEPT", "REJECT")`；BLINDSPOT 允许带**部分**读数。
4. **K3 把「无位移」误判为「方向为 0」**：原实现把 `dx ≈ 0` 返回 `0.0`，
   而 `0.0` 在 `d1 * d2 < 0` 里既不触发 REJECT 也不触发缺料分支 —— **静默通过**。
   修法：无位移返回 `None`（不可判），并在判据里把 `None` 与 `0.0` 一并归入「无从判方向」。

5. **依赖闭包登记表漏了仓内包 `wm_bridge`**（**冻结态全量回归唯一的红**，2950 passed / 1 failed）。
   现场：`tests/test_gate_dependency_closure.py::test_every_hard_third_party_import_is_declared` 报
   `· wm_bridge ← tests/test_film_contract_guard.py:44..51, tests/test_film_criteria_guard.py:44..46`。
   取证根因：该判据用 `LOCAL_TOP` 过滤「仓内顶层可导入名」，而 `wm_bridge` **是仓内包却不在表里** ——
   `git ls-files bridges/` = 73 个文件（git 跟踪 ⇒ 仓内件）；pyproject 的 `packages.find` 只收 `lingshu*`
   （⇒ 它不是发行包，既不能在 pyproject 声明，也不该被要求声明）；它住在 `bridges/blender/`（**不在仓根**），
   所以「顶层名」这一维看不出它是不是仓内的 —— 只能靠人工登记。
   触发条件：`tests/` 下**第一次真的 import 它**。此前只有 `test_issue427_shade_paint_guard.py` 提到
   `wm_bridge`，但那两处都在**注释与路径字符串**里、不是导入；影视层两个守卫是首个真 import 它的用例
   （须自行把 `bridges/blender` 插进 `sys.path`），于是这个**自 #286 起就存在**的登记缺口第一次暴露。
   修法：`LOCAL_TOP` 补入 `wm_bridge`（并加注「非仓根仓内包只能靠人工登记」），
   同时在影视判据守卫新增 **[H] 反向守卫组** —— 把「影视守卫 ⇒ 必须登记 `wm_bridge`」这条耦合
   显式钉死在**我自己的文件里**：谁删了登记表，[H] 立刻点名原因，而不必去翻 2950 项回归。
   变异自证：摘掉登记表里的 `wm_bridge` ⇒ 依赖闭包判据**与 [H] 同时变红**；还原 ⇒ 双绿。

> 这一处与前四处的性质不同：前四处是**我写错了**，这一处是我**踩到了一个既有的登记缺口**。
> 它同样只有靠「跑全量回归」才能暴露 —— 单跑影视守卫永远是绿的。这正是不许用「本地局部绿」

## 八、诚实边界与不适用条件

**本架构宣称的**：
- 视听语言手艺的**可声明化、可判定化、可复现化**；
- 把「哪里难看」变成可回归的**读数**；
- LLM 的不确定性被**隔离在编译期**，产物侧确定性不受污染。

**本架构不宣称的**：
- ❌ **不宣称艺术创造力**。它固化**手艺**，不产出**取向**。取向归使用者（DEFER）。
- ❌ **不宣称「好看」可被完全判定**。相当一部分（色彩情绪、母题选择、个人风格）**明确不可判定**，本方案把它们登记为 G3/DEFER，而不是假装能算。
- ❌ **不宣称像素级写实**——使用者已明确排除。
- ❌ **不宣称 LLM 编译的结果一定好**。只保证「可判定、可复跑、可迭代」。

**不适用条件**：
1. 不适用于**无权威依据的纯实验风格**——此类应走 BLINDSPOT 记档并驱动补理论，**不得硬编码**（第 12 条）；
2. 不适用于**实时交互**场景——本架构是离线确定性产线；
3. 不适用于**像素级写实**目标；
4. 不适用于把**风格主张当规范**去硬拦创作（G1 门只收 `[标准]`/`[共识]`）；
5. 不适用于**把「可以重依赖」误读为「可以随便依赖」**——重依赖必须按 §3.5 落进声明面（sub-extra ＋ 函数内 import ＋ 不进 `full`），并过守卫；
6. 不适用于**竖屏 9:16 交付**——本版画幅已裁为 **16:9 横屏**（D4），§3.4 的字幕安全区（title safe 0.80 / action safe 0.90，EBU R95）与构图参数均为横屏取值；竖屏须独立补安全区、行宽与构图，**不得复用本版数值**。

> **依赖口径澄清（2026-10-15 使用者裁定）**：身体库**可以重依赖**。
> 但 `D-005`（零依赖）**只约束 `world/` 的核心路径**，不约束本新层；
> 而 `B2`（不把 bpy 带进 lingshu）**仍然全仓有效**。详见 §3.5.2。
